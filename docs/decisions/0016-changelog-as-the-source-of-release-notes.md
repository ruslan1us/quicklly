# 0016. CHANGELOG.md as the single source of release notes

- **Status:** Accepted
- **Date:** 2026-10-07

## Context

GitHub releases used notes generated by GitHub from the commit history, which list commits rather
than user-facing changes, and users had no way to see what changed from inside the application.
Writing the notes separately for each place would produce copies that drift apart.

## Decision

Keep a `CHANGELOG.md` in the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format. The
release workflow extracts the `## [X.Y.Z]` section as the GitHub release body and fails without it.
The `/changelog` window bundles the file at build time and renders it. User-visible changes add an
entry under `## [Unreleased]` as they are made.

## Consequences

- One text serves the repository, the release page and the application.
- A release cannot be published without notes.
- The heading and list structure is parsed by two consumers (an `awk` script in the workflow and
  `parseChangelog` in the window) and must stay in the documented format.

See [Release](../release.md#changelog).
